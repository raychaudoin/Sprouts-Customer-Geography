## Record semantics to implement

Use concise repository guidance/templates/conventions. Do not create long forms or status cockpits.

### LAUNCH

Must make clear:

- record type;
- initiative/current action;
- controlling Work Order;
- destination role/surface;
- PR/exact candidate head when applicable;
- requested action and material exclusions;
- task-specific execution profile when relevant;
- expected next control point.

### RESULT

Must make clear:

- record type;
- initiative/action performed;
- exact resulting PR/head candidate;
- concise change summary;
- validation/CI performed or pending;
- safeguards/exclusions preserved;
- unresolved gap/deviation if any;
- next control point.

### REVIEW

Must make clear:

- record type;
- review role/surface;
- exact PR/base/head reviewed;
- disposition such as `PASS` or `REWORK REQUIRED`;
- material findings/deviations;
- safety/evidence concerns;
- next control point.

The implementation must be concise enough that Ray need not carry completion/review reports between Projects in the normal path.
